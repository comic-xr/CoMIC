## SLIDE 2: Project Recap (1 slide only)

**Research Question:** How well can VLMs understand data visualizations — and what happens when charts move from 2D to 3D?

**What we did:**
- Evaluated GPT-5.4 on the ChartX benchmark (6,000 chart images, 18 chart types)
- Tested 5,720 2D images + 280 3D bar chart images
- Each image has a question + ground truth answer from the dataset

**Why it matters:**
- Immersive analytics (VR/AR) uses 3D visualizations by default
- If VLMs can't understand 3D charts, they can't assist users in VR
- No prior work evaluates VLMs across this many chart types

1. Load chart image + question from ChartX
2. Send to GPT-5.4 via API
3. Parse free-text response
4. Score: 10% numeric tolerance + keyword matching
5. Cache all responses for reproducibility

**Scale:** 5,713 successful 2D evaluations + 280 3D evaluations

## SLIDE 6: KEY RESULT — The 43-Point Gap

**Position-encoded charts (bar, line): ~92-95%**
**Area-encoded charts (treemap, bubble): ~52-71%**
**Gap: 43.7 percentage points**

This is NOT random — it follows Cleveland & McGill's 1984 perceptual hierarchy:
- Position along common scale -> MOST accurate (bar, line)
- Length -> accurate (funnel)
- Angle/arc -> moderately accurate (pie, rings)
- Area -> LEAST accurate (treemap, bubble)

VLMs have learned the same perceptual hierarchy as humans.

## SLIDE 7: KEY RESULT — 3D Collapse

| Condition | Accuracy |
|-----------|----------|
| 2D bar_chart_num | 92.1% |
| 2D bar_chart | 87.7% |
| **3D-Bar** | **59.3%** |

**26.4-32.8 percentage-point drop from 2D to 3D**

Why? VLMs see a single static 2D projection of a 3D chart:
- Perspective distortion (bars look shorter from far away)
- Occlusion (front bars hide back bars)
- Foreshortening (depth compresses heights)
- No ability to rotate the view (unlike humans in VR)

---

## SLIDE 8: KEY FINDING — Invisible Ground Truth Problem

**Why do treemaps score 51.6%?**

[Show treemap image side-by-side with ground truth]

The treemap image shows: colored rectangles with category names
The ground truth expects: exact percentages (e.g., "20%")
The problem: **those percentages are NOT shown on the image**

- The VLM must estimate percentages from rectangle area alone
- Stevens' Power Law: area perception exponent ~0.7 (systematic underestimation)
- Even humans can't extract exact values from treemaps without labels

**This is a benchmark design issue, not a VLM failure.**

ChartX's own paper acknowledges: "the column label of values is usually invisible" for treemaps.

**Key patterns:**
- Treemap: impossible task (no numbers visible)
- Radar: overlapping series + strict format matching
- Bubble: size encoding is perceptually ambiguous
- Area: confusion between stacked vs individual values

## SLIDE 10: Design Guidelines for VLM-Assisted Immersive Analytics

Six evidence-based guidelines:

1. **Use position-encoded charts** (bar, line) for VLM-readable visualizations
2. **Always include numeric labels** — transforms estimation to text reading
3. **Flatten 3D before VLM processing** — render 2D projections or provide data tables
4. **Use tiered scoring tolerance** — 5% for bar/line, 25% for treemap/bubble
5. **Structure prompts as describe -> extract -> reason** pipelines
6. **Maintain a VLM-interpretable 2D layer** beneath 3D immersive rendering

## SLIDE 12: Limitations

- Single model (GPT-5.4 only) — cross-model comparison needed
- One question per chart in ChartX — limited task diversity
- 3D evaluation limited to bar charts only (ChartX has one 3D type)
- Automated scoring may miss semantically correct but differently formatted answers
- No immersive (Unity/VR) rendering condition tested yet

## SLIDE 13: Future Work

1. **DXR + Unity integration** — render charts in immersive VR environment
2. **Multi-viewpoint evaluation** — send 3-6 camera angles to VLM
3. **Structured grounding** — image + system state JSON (data, encodings, camera pose)
4. **Human study** — compare VLM-assisted vs unassisted chart comprehension in VR
5. **Multi-model comparison** — Claude, Gemini, open-source VLMs
6. **Prompt engineering** — chain-of-thought, describe-extract-reason pipelines

---

## SLIDE 14: Summary

**Three key findings:**

1. **85.7% on 2D, 59.3% on 3D** — VLMs are strong on flat charts but collapse in 3D

2. **43-point gap follows perceptual science** — position-encoded charts (92-95%) >> area-encoded charts (52-71%), exactly as Cleveland & McGill predicted in 1984

3. **Invisible ground truth** — treemap failures are partly a benchmark design problem, not purely a VLM limitation

**One-line takeaway:**
VLM chart comprehension follows the same perceptual hierarchy as human vision — position is easy, area is hard, 3D makes everything worse — and we provide the first design guidelines for VLMs in immersive analytics.

## ANTICIPATED Q&A

**Q: Why only GPT-5.4? Why not compare multiple models?**
A: Budget and scope constraints for a course project. Prior Phase 1 results with Claude and Gemini showed similar patterns. GPT-5.4 is the latest and strongest model available.

**Q: How do you know the invisible ground truth is a real problem and not just GPT being bad at treemaps?**
A: Three reasons: (1) ChartX's own paper acknowledges values are "usually invisible" for treemaps; (2) Cleveland & McGill showed humans also can't extract exact values from area encoding; (3) the accuracy pattern maps precisely to information visibility — charts with labels score 90%+, charts without score 50-70%.

**Q: What would you do differently with more time?**
A: Multi-model comparison, DXR/Unity immersive rendering condition, structured grounding experiment (image + data JSON), and prompt engineering (chain-of-thought).

**Q: How does this connect to immersive analytics?**
A: If VLMs score 59% on 3D bar charts from a dataset, they'll perform even worse on real-time VR screenshots with lighting, shadows, and motion blur. Our design guidelines address this — especially #3 (flatten 3D) and #6 (maintain VLM-interpretable 2D layer).

**Q: Is 85.7% good enough for practical use?**
A: For simple chart types (bar, line, pie), yes — 90%+ is usable. For treemaps and radar, no — 52-68% means the VLM gives wrong answers nearly half the time. The design guidelines address when to trust VLM outputs based on chart type.
